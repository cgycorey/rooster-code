01 — Overview

What is Rooster Code?

Rooster Code is a custom coding agent that gives you fine-grained control over how AI agents work with your codebase. It runs as a CLI, a background daemon, or a team orchestrator — all configurable from a single codebase.

CLI & Chat

Interactive TUI with slash commands, prompt injection, and session management

Daemon Mode

Long-running background service with Unix socket, Telegram adapter, and cron scheduling

Team Orchestration

Multi-agent dispatch with AgentPool, mailboxes, health tracking, and background tasks

02 — Core Feature

Team Orchestration

Dispatch tasks to specialized agents in parallel. Monitor progress in real-time with /team status and review output with /team log.

/team create review-team security-auditor code-reviewer Dispatch security-auditor to review for HIGH vulnerabilities Dispatch code-reviewer to check async patterns and error handling /team status [OK] task_1 completed team-security-auditor [..] task_2 in_progress team-code-reviewer

AgentPool

Persistent agent instances with per-member mailboxes and health tracking

Background Tasks

Fire-and-forget dispatch with status notifications and task output retrieval

Recovery

Automatic member recreation on failure with fallback state restoration

03 — Core Feature

Goal System

Define persistent objectives that survive session restarts. The agent receives your goal as part of its system prompt — keeping it focused across turns.

/goal set

Define an active goal with JSON persistence in ~/.rooster-code/

/goal work

Auto-loop mode — agent works autonomously, stops on GOAL_MET

/goal check

Manual progress assessment with goal-specific prompt

/goal set "Add O_NOFOLLOW to all file ops" /goal work Turn 1: Checking codebase... Found 3 unprotected os.open calls Turn 2: Applied O_NOFOLLOW. Running tests... GOAL_MET Goal met! Loop stopped.

04 — Security

Hardened by Default

Every file operation is protected against TOCTOU races. Multiple security audits — zero critical findings.

O_NOFOLLOW

All 7 os.open calls use O_NOFOLLOW to atomically prevent symlink attacks on file reads and writes

Atomic Writes

Lock files isolated to .lock suffix. mkstemp + os.replace pattern prevents zero-byte corruption on crash

Socket Hardening

Unix socket chmod 0o600 after bind. Telegram tokens via env var — never in /proc/cmdline

SSE Reconnect

MCP transport with 3-retry exponential backoff (2s→4s→8s), orphaned request cleanup

06 — Integration

MCP Transport

Custom SSE/HTTP MCP client with automatic reconnect — fills the gap the SDK leaves for non-stdio transports.

Persistent SSE Stream

Single GET /sse for endpoint discovery and response reading, correlated by request ID

Reconnect Loop

3 retry attempts with exponential backoff: 2s → 4s → 8s. Orphaned futures cleaned up on disconnect

Inline SSE Fallback

Some MCP servers return SSE in POST responses — handled via _parse_inline_sse fallback

09 — Agent Teams

Multi-Agent Codebase Evaluation

Spawn specialized review agents in parallel. Each agent gets a narrow contract and reports findings independently. Consolidate for a complete picture.

🛡 Security Auditor

Scans for vulnerabilities, hardcoded secrets, TOCTOU races, injection risks. Reports HIGH/CRITICAL only.

📝 Code Reviewer

Python patterns, async correctness, error handling, type hints, code duplication. MEDIUM+ findings.

🔍 Silent-Failure Hunter

Bare excepts, swallowed exceptions, missing logs, fire-and-forget gaps. All severities.

/team create codebase-eval security-auditor code-reviewer silent-hunter # Dispatch all 3 in parallel Dispatch security-auditor to scan for HIGH/CRITICAL security issues Dispatch code-reviewer to check for async patterns and error handling Dispatch silent-hunter to scan for swallowed exceptions and dead code /team status [..] task_1 in_progress security-auditor [..] task_2 in_progress code-reviewer [..] task_3 in_progress silent-hunter ... all 3 complete ... /team status [OK] task_1 completed security-auditor [OK] task_2 completed code-reviewer [OK] task_3 completed silent-hunter
